One of the pitfalls of rolling your own crypto can be generating your own parameters
to be used in a tried and tested cryptographic algorithm. Take Diffe-Hellman[^DH] (DH), 
which has been in use for decades and secured countless data. The obvious way to mess
up DH params is to generate parameters that are too small and can be brute forced. The more
subtle way is to mess up is to generate parameters whose algebraic structure can be exploited
to recover secret material efficiently.

# Mathematical Foundations

In DH we have a couple parameters that we need to select:

- `p` - a prime used to define a multiplicative group of integers `mod p`
- `g` - a generator within the multiplicative group
- `q` - the order of `g` i.e. the number of distinct group elements of the form `g^x mod p`

We then use these parameters to establish a shared secret between Alice and Bob using DH.
Alice selects a secret `a` and Bob selects a secret `b`. Both these secrets are integers in
the range `[1, q-1]`[^order]. Alice sends `A = g^a mod p` to Bob and Bob sends
`B = g^b mod p`. Alice then computes `B^a mod p = g^(ba) mod p` and Bob computes
`A^b mod p = g^(ab) mod p`, which are equivalent and constitute the shared secret. Note that
`p`, `g` and `q` are publicly known. `A` and `B` should also be considered non-secret material.

```python
class DH:
    def __init__(self, g: int, p: int, q: int):
        self.g = g
        self.p = p
        self.secret = randint(1, q-1)
    
    def public_key(self) -> int:
        return pow(self.g, self.secret, self.p)
    
    def shared_secret(self, other_public_key: int) -> int:
        return pow(other_public_key, self.secret, self.p)
```

If `q` is equivalent to `p-1` then `g` can generate every element in the multiplicative
group of integers `mod p`[^primitiveroot]. If `q` is less than `p-1` then `g` generates
a subgroup of the multiplicative group of integers `mod p`. This means that all elements
of the subgroup are part of the multiplicative group, but the subgroup is strictly smaller.
In fact, the subgroup will have exactly `q` elements.

As an example, suppose `p = 7`. This means our multiplicative group `mod 7` is 
`{1,2,3,4,5,6}`[^coprime]. We examine two generators, `g = 3` and `g = 2`. In the case of 
`g = 3` we have the following values that can be generated
```
3^1 mod 7 = 3
3^2 mod 7 = 2
3^3 mod 7 = 6
3^4 mod 7 = 4
3^5 mod 7 = 5
3^6 mod 7 = 1
```
Once we hit `1` the sequence of values repeats. Note that `q = 6 = p-1` so `g = 3` generates
the full multiplicative group `mod 7`. Let's take a look at `g = 2`
```
2^1 mod 7 = 2
2^2 mod 7 = 4
2^3 mod 7 = 1
```
In this case we have a subgroup `{1,2,4}` of size `q = 3` generated by `g = 2`. If you want to
experiment a bit with changing `g` and `p` to see how the generated groups change you can use
the code below

```python
from math import gcd

def gen(g: int, p: int):
    if gcd(g, p) != 1:
        raise ValueError("g and p must be coprime")

    g %= p
    current_element = g
    group = {g}

    while current_element != 1:
        current_element = (current_element * g) % p
        group.add(current_element)
    
    print(f"Generated group = {group}")
    print(f"Group order (q) = {len(group)}")
```

# Attack Outline

Suppose that we have a protocol where we establish a shared secret with Bob using DH. Bob then
uses the shared secret, let's call it `k`, as the key for generating a tag using the HMAC
algorithm. He then sends us back the message `m` the HMAC was computed on and the tag `t` for
that message. We can then use our shared secret to recompute the tag from the message. This
allows us to establish that we have derived the same shared secret via DH without actually
sending the secret over the wire. 

```python
from hashlib import sha3_256
from hmac import HMAC
from math import ceil

class Bob:
    def __init__(self, dh: DH):
        self.dh = dh
    
    def protocol(self, A: int) -> tuple[bytes, bytes]:
        k = self.dh.shared_secret(A)
        m = b"crazy flamboyant for the rap enjoyment"
        return mac(k, m)

def mac(k: int, m: bytes) -> tuple[bytes, bytes]:
    k_bytes = _int_to_bytes(k)
    t = HMAC(k_bytes, m, sha3_256).digest()
    return (m, t)

def _int_to_bytes(k: int) -> bytes:
    byte_size = ceil(k.bit_length() / 8)
    return k.to_bytes(byte_size)
```

Recall that `k = A^b mod p` where `A` is the value we sent Bob in DH and `b` is Bob's secret
value. It is actually quite trivial to recover `b` from `(m, t)` alone. All we need to do is
select a trial value `b'`, compute `k'` from it, and then use that to compute `(m, t')` and
check it `t == t'`. If they are equal then we have recovered Bob's secret.

```python
# dh represents our DH context including our public value A
def recover_secret(dh: DH, m: bytes, t: bytes) -> int:
    A = dh.public_key()
    b_candidate = 1
    k = pow(A, b_candidate, dh.p)

    while mac(k, m) != (m, t):
        b_candidate += 1
        k = pow(A, b_candidate, dh.p)
    
    return b_candidate
```

In practice this doesn't work because `q` is a very large number and `b` is in the range `[1. q-1]` so the computational complexity of brute forcing `b` is beyond modern hardware. But what if `q` was smaller? We control the value `A` that is exponentiated by `b`, what if we
pick `A` such that it is in a small subgroup of order `q'` that _is_ small enough to brute
force? While `b` is still in a large range, we note that `A^b = A^(b mod q') mod p` when A
is an element of order `q'`. This means we can recover a residue of `b` via brute force,
`b' = b mod q'`. If we find enough residues in small subgroups we can, as we will later
explain, efficiently combine these residues to find the value of `b`.

# Finding Small Subgroups

```python
from random import randint

def generator_for_order(q: int, p: int) -> int:
    quotient, remainder = divmod(p-1, q)
    
    if remainder != 0:
        raise ValueError("q must divide p-1 evenly")

    g = 1
    
    while g == 1:
        base = randint(1, p)
        g = pow(base, quotient, p)
    
    return g
```

[^DH]: See [wikipedia](https://en.wikipedia.org/wiki/Diffie%E2%80%93Hellman_key_exchange) for a refresher on Diffie-Hellman.
[^order]: Why are they in this range? Because the order of `g` is `q`. If e.g. `a` were some value greater than `q-1`, then there is `a' = a mod q` such that `g^a = g^a' mod p`.
[^primitiveroot]: If a generator `g` has order `q = p-1`, we call `g` a primitive root modulo `p`.
[^coprime]: Note that `0` is not part of this group as it is not coprime to `p`.
